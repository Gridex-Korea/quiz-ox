|---|---|---|---|
| FR-1 | 참가자는 QR 코드를 스캔해 접속 URL(방 코드 포함)로 들어올 수 있다 | 필수 | [[screens]] |
| FR-2 | 참가자는 전화번호와 이름(또는 별명)을 입력해 입장한다. 전화번호는 한국 휴대폰 형식으로 검증·정규화한다 | 필수 | [[ADR-0003-phone-identity]] |

| FR-4 | 입장 시 아바타(미니미)가 자동 배정되고, 참가자는 다른 모양으로 바꿀 수 있다 | 권장 | [[screens]] |

### 게임 진행

| ID | 요구사항 | 우선순위 | 관련 설계 |
|---|---|---|---|
| FR-10 | 사회자는 문제 목록(지문, 정답, 제한시간, 선택적 이미지·해설)을 사전에 등록한다. CSV/JSON 업로드와 화면 내 편집을 모두 지원한다 | 필수 | [[data-model]] |
| FR-11 | 사회자는 문제 공개 → 타이머 시작 → 정답 공개 → 다음 문제 순서를 버튼으로 진행한다 | 필수 | [[game-flow]] |
| FR-12 | 타이머는 서버 시각을 기준으로 모든 화면에서 같은 값으로 표시된다 | 필수 | [[realtime-protocol]] |
| FR-13 | 참가자는 제한시간 안에 O 또는 X를 선택하고, 마감 전까지 선택을 바꿀 수 있다. 마지막 선택이 답이다 | 필수 | [[game-flow]] |
| FR-14 | 마감 이후 도착한 답은 거절한다(네트워크 지연 보정용 유예 수백 ms 허용) | 필수 | [[game-flow]] |
| FR-15 | 시간이 끝나면 스크린에 O 인원과 X 인원(미응답 인원 포함)이 표시된다 | 필수 | [[screens]] |
| FR-16 | 정답 공개 시 오답자는 자동으로 경고 1회를 받고 대기실로 이동한다. 대기실 참가자는 일반 문제에 답할 수 없고 관전만 한다 | 필수 | [[game-flow]] |
| FR-17 | 오답이 누적 2회가 되면(일반 라운드·패자부활전 구분 없음) 참가자는 퇴장 처리되어 연결이 끊기고, 폰에는 탈락 안내 화면만 남는다. 재접속은 거절된다 | 필수 | [[game-flow]] |
| FR-18 | 미응답은 오답으로 처리한다(확정 규칙, 설정 없음) | 필수 | [[game-flow]] |
| FR-19 | 사회자는 직전 라운드 결과를 취소(되돌리기)할 수 있고, 특정 참가자를 수동으로 복구·퇴장시킬 수 있다 | 필수 | [[game-flow]] |
| FR-20 | 사회자는 진행 중 타이머를 연장(+10초)하거나 조기 마감할 수 있다 | 권장 | [[realtime-protocol]] |
| FR-21 | 마지막 문제가 끝나거나 사회자가 종료하면 최종 생존자 목록이 스크린에 표시된다 | 필수 | [[screens]] |
| FR-27 | 최종 결승(추가 문제·가위바위보)은 앱 밖에서 진행한다. 결승이 끝나면 사회자가 생존자 중 우승자를 지정하고, 스크린에 왕관 연출이 나온다 | 권장 | [[screens]] |

| ID | 요구사항 | 우선순위 | 관련 설계 |
|---|---|---|---|
| FR-22 | 사회자는 라운드 정리가 끝난 뒤 대기실에 1명 이상 있으면 패자부활전을 열 수 있다. 패자부활전에서는 대기실 참가자만 답하고 무대 생존자는 관전한다 | 필수 | [[game-flow]] |
| FR-23 | 패자부활전 정답자는 무대로 복귀한다. 스트라이크는 1로 유지되어 다음 오답에 바로 퇴장한다. 오답자·미응답자는 퇴장한다 | 필수 | [[game-flow]] |
| FR-24 | 문제 은행에서 패자부활전용 문제를 표시해 둘 수 있고, 사회자는 미출제 문제 어느 것이든 패자부활전으로 낼 수 있다 | 필수 | [[data-model]] |
| FR-26 | 패자부활전은 중반 1회가 기본 계획이다. 콘솔은 설정된 예정 시점(문제 번호)의 정답 공개 뒤 "다음 단계" 버튼을 "패자부활전 시작"으로 바꿔 안내한다. 예정 외 추가 부활전은 비상용으로만 2단계 확인 후 열 수 있다 | 필수 | [[screens]] |
| FR-25 | 참가자 폰은 자기 상태에 맞는 안내를 보여준다: 대기실은 일반 라운드에서 "관전 중", 패자부활전에서 "맞히면 복귀, 틀리면 탈락"; 무대 생존자는 패자부활전 동안 "관전 중" | 필수 | [[screens]] |

## 비기능 요구사항

| ID | 항목 | 기준 |
|---|---|---|
| NFR-1 | 동시 접속 | 참가자 100명(예상 50명의 2배) + 스크린 1 + 콘솔 1이 WebSocket으로 동시 연결 |
| NFR-2 | 반응 지연 | 답변 탭 → 스크린 반영 p95 500ms 이하(참가자 네트워크 정상 시) |
| NFR-3 | 집계 지연 | 타이머 종료 → 인원 표시 1초 이하 |
| NFR-4 | 타이머 정확도 | 화면 간 표시 편차 300ms 이하, 마감 판정은 서버 시각 단일 기준 |
| NFR-5 | 재접속 | 폰 화면 잠김·새로고침·네트워크 끊김 후 10초 안에 자동 복귀 |
| NFR-6 | 브라우저 | iOS 16+ Safari, Android Chrome 최근 2년 버전. 스크린·콘솔은 데스크톱 Chrome |
| NFR-7 | 가용성 | 행사 시간 동안 서버 1대가 계속 켜져 있어야 함(스케일 투 제로 금지) |
| NFR-8 | 개인정보 | 전화번호는 URL·로그·스크린에 노출하지 않음, 저장 시 해시 없이 원문 보관하되 접근은 콘솔 한정, 행사 후 삭제 |
| NFR-9 | 렌더링 | 스크린 아바타 100개에서 30fps 이상(DOM + CSS transform) |

## 제약

- 개발 인력은 사회자 본인 + Claude Code이며, 운영도 사회자 혼자 한다. 운영 절차는 버튼 몇 개로 끝나야 한다.
- 행사장에 인터넷이 없다. 노트북은 휴대폰 핫스팟, 참가자는 자기 이동통신 데이터를 쓴다. 페이로드는 작게, 재접속은 자동으로, 핫스팟은 예비 폰을 하나 더 준비한다.
- 사용자에게 이미 GCP Cloud Run 배포 경험과 절차(스킬)가 있다. 배포 대상은 이를 우선 활용한다([[ADR-0004-cloud-deploy]]).
- 개인정보보호법상 전화번호 수집은 목적 고지와 동의가 필요하다. 폼 문구는 실제 사용 전 확정해야 한다.
