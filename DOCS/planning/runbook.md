# 운영 매뉴얼(런북)

사회자 혼자 준비·진행·정리를 끝내기 위한 순서표. 콘솔 화면 구성은 [[screens]] 참고.

## 준비물

| 항목 | 비고 |
|---|---|
| 노트북 1대 | 콘솔(`/host`)과 스크린(`/screen`)을 **다른 창**으로 띄움. 스크린 창만 프로젝터로 |
| 휴대폰 핫스팟 2대 | 노트북 인터넷용. 하나는 백업. 테더링 데이터 한도 확인 |
| 프로젝터/TV | 1920×1080 권장. 스크린 창 전체화면(F11) |
| 문제 파일 | CSV 또는 JSON. 일반 문제 10개 내외 + 패자부활전용 1~2개(`kind=REVIVAL`) |
| 서버 정보 | 공개 URL, 사회자 PIN, 스크린 키. 종이에 적어 둘 것(핫스팟 끊기면 검색 불가) |

## D-1 (전날)

- [ ] 배포 동결. 이후 `gcloud run deploy`·재배포 금지(인스턴스가 바뀌면 진행 상태가 사라짐) → [[ADR-0004-cloud-deploy]]
- [ ] `https://<서비스URL>/api/health` 가 `{"ok":true}` 인지 확인
- [ ] 콘솔 로그인 → 설정 탭: 제한시간(기본 15초), 부활전 시점(기본 5번 문제 뒤), 이동 공개 시점(기본 4번까지) 확인
- [ ] 문제 탭: 문제 가져오기 → 정답 O/X와 순서 검토. 패자부활전용 문제가 ♻ 표시인지 확인
- [ ] 설정 탭에서 **QR 이미지 저장**(인쇄용). 스크린에도 나오지만 인쇄물이 있으면 뒷자리에서 편함
- [ ] 리허설: 본인 폰으로 `/join` 입장 → 콘솔에서 입장 마감 → 문제 1개 진행 → **게임 초기화(문제 유지)** 로 되돌리기
- [ ] 전화번호 안내 문구가 폼에 맞게 나오는지 확인 → [[ADR-0003-phone-identity]]

## 당일 순서

1. 핫스팟 켜고 노트북 연결. 백업 폰 핫스팟도 미리 켜 둔다.
2. 브라우저 창 A: `/host` 로그인(PIN). 창 B: `/screen` → 스크린 키 입력 → 프로젝터로 보내고 전체화면.
3. 스크린 오른쪽 아래 **🔊 사운드 켜기** 클릭(한 번만).
4. 스크린에 QR과 방 코드가 보이면 참가자 입장 안내. 콘솔 참가자 탭에서 인원 확인. 이름이 부적절하면 **퇴장**.
5. 규칙 멘트 3줄: "틀리면 대기실(관전), 두 번 틀리면 탈락, 중간에 패자부활전 한 번."
6. **입장 마감** 클릭. 이후 새 번호는 들어올 수 없고, 기존 참가자는 같은 번호·이름으로 복귀만 가능.
7. 문제마다: **문제 공개** → 읽어 주기 → **타이머 시작** → (자동 마감) → **정답 공개** → 해설 → **다음 문제**.
   - 큰 보라색 버튼 하나만 누르면 순서대로 진행된다.
   - 초반 4문제는 아바타 이동이 실시간으로 보이고, 5번부터는 마감 때 한꺼번에 공개된다.
8. 5번 문제 정답 공개 뒤 큰 버튼이 **패자부활전 시작**으로 바뀐다. 대기실 인원을 확인하고 누른다.
   - 무대가 교대된다. 부활전 정답자는 무대 복귀(남은 기회 1회), 오답·미응답은 탈락.
   - 부활전을 건너뛰려면 옆의 "부활전 없이 다음 문제".
9. 문제가 끝나거나 생존자가 충분히 줄면 **게임 종료** → 스크린에 생존자 명단.
10. 생존자를 무대로 불러 추가 문제·가위바위보로 결승(앱 밖). 끝나면 콘솔에서 **우승자 지정** → 왕관 연출.

## 사고 대응

| 상황 | 대응 |
|---|---|
| 정답을 잘못 입력한 채 공개했다 | **판정 취소** → 문제 탭에서 정답 수정 → **정답 공개** 다시. 탈락자는 자동 복귀 |
| 참가자가 "눌렀는데 안 됐다"고 항의 | 콘솔 참가자 탭에서 그 사람의 선택 열을 확인. 미응답이면 규칙대로 오답. 네트워크 사고가 분명하면 **복구** |
| 여러 명이 동시에 못 답했다(핫스팟·통신 장애) | 답변 중이면 **라운드 취소** → 타이머 다시. 이미 공개했으면 **판정 취소** 후 라운드 취소 |
| 노트북 인터넷이 끊겼다 | 백업 핫스팟으로 전환. 서버는 클라우드에 있어 참가자 진행은 유지되며 콘솔·스크린은 자동 재접속 |
| 참가자 폰이 꺼졌다/새로고침했다 | `/join`에서 같은 번호·같은 이름으로 다시 입장하면 자리가 복구된다 |
| 탈락자가 항의한다 | 콘솔 참가자 탭 → **복구**(탈락 → 대기실) |
| 무대 생존자가 0명이 됐다 | 콘솔 경고가 뜬다. 대기실이 있으면 **추가 부활전(비상용)**, 없으면 **판정 취소** 또는 종료 |
| 문제가 바닥났는데 생존자가 많다 | 문제 탭 **+ 문제 추가**로 즉석 출제(뒤에 붙는다) 또는 종료 후 오프라인 결승 |
| 스크린 창이 프로젝터에서 사라졌다 | `/screen` 다시 열기. 현재 상태로 즉시 복원된다(연출 없이 배치) |
| 서버가 재시작됐다 | 마지막 상태로 복구된다. 답변 중이었다면 문제 화면으로 돌아오니 타이머만 다시 시작 |
| 콘솔 PIN을 5번 틀려 잠겼다 | 10분 뒤 다시 시도. 급하면 다른 네트워크(폰)로 접속 |

## 종료 후

- [ ] 설정 탭 → **참가자 CSV 내보내기**(경품 지급용, 전화번호 포함)
- [ ] 경품 연락이 끝나면 **전화번호 전체 삭제**(되돌릴 수 없음). 7일이 지나면 자동 삭제되지만 직접 지우는 것이 원칙
- [ ] 내려받은 CSV는 경품 지급 후 파기
- [ ] GCS 스냅샷 버킷의 `ox.sqlite` 삭제(전화번호 포함)
- [ ] Cloud Run 인스턴스 최소값을 0으로 내리거나 서비스 삭제(비용)
- [ ] 다음 행사 때는 콘솔 **게임 초기화**로 새 방 코드 발급

## 행사용 아바타 봇 (초반 무대 채우기)

실제 참가자와 함께 뛰는 가상 참가자 10명. 각자 정답률(기본 70%±20)이 달라 자연스럽게 갈리며, 시간을 끌다 고르고 가끔 마음을 바꾼다. **5번 문제 정답 공개까지 함께 뛰고 3초 뒤 명단에서 조용히 사라진다**(탈락으로 집계되지 않음, CSV에도 남지 않음). 우승할 일도 없다.

```bash
# 사회자 노트북에서, 입장 접수 중에 실행. 서비스 URL·PIN을 실제 값으로.
npm run bots -- --count 10 --until 5 --url https://<서비스URL> --pin <사회자PIN>
```

- 이름은 민준·서연·도윤·하은·지호·수아·예준·지우·시우·하윤 순으로 고정이며 번호는 `0108-100-000x` 가짜 번호다.
- 정답을 읽기 위해 사회자 PIN이 필요하지만 진행 명령은 절대 내리지 않는다.
- 콘솔에서 **게임 초기화**를 하면 봇들이 알아서 다시 입장한다. 끝까지 같이 뛰게 하려면 `--until 0`.
- 본행사 D-1 리허설에서 봇만으로 한 번 끝까지 돌려 보면 콘솔 버튼 순서가 손에 익는다.

## 개발 환경 요약

```bash
npm install
npm run dev          # 서버 3000 + 웹 5173 (PIN 1234, 스크린 키 screen)
npm test             # 서버 단위·통합 테스트
npm run simulate -- --players 100 --questions 5   # 가상 참가자 부하 테스트(서버 실행 중일 때)
npm run bots -- --count 10 --until 5               # 리허설·행사용 아바타 봇(서버 실행 중일 때)
npm run build && npm start                         # 운영 모드(3000, HOST_PIN·SCREEN_KEY 환경변수 필요)
```
