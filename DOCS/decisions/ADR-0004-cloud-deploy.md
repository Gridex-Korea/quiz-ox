# ADR-0004 행사 서버는 클라우드 단일 인스턴스로 배포하고, 현장은 휴대폰 핫스팟과 참가자 데이터로 접속한다

## 맥락

참가자는 QR 코드를 스캔해 접속한다. 행사장 WiFi는 수십~수백 대의 폰이 붙으면 불안정해지고, AP 격리 설정 때문에 같은 WiFi 안의 노트북 서버에 폰이 접근하지 못하는 경우도 흔하다. 반면 참가자 폰의 이동통신 데이터는 대부분 안정적이다. 사용자는 GCP Cloud Run 배포 경험과 절차(사내 스킬)를 이미 가지고 있다. [[ADR-0002-single-instance-state]]에 따라 서버는 정확히 1개여야 한다.

행사장 조건 확인 결과(2026-09-16): WiFi·유선 인터넷이 없다. 사회자 노트북은 휴대폰 핫스팟으로 연결하고, 참가자 약 50명은 QR 코드로 접속해 자기 이동통신 데이터를 쓴다. 휴대폰 핫스팟은 동시 접속 기기 수가 보통 10대 내외로 제한되므로, 참가자 50명을 핫스팟에 붙여 노트북 서버에 접속시키는 LAN 모드는 성립하지 않는다.

## 결정

- 본 배포는 **GCP Cloud Run, 인스턴스 정확히 1개**로 한다: `--min-instances=1 --max-instances=1`, `--no-cpu-throttling`(연결 사이에도 타이머가 돌아야 함), `--timeout=3600`(WebSocket 최대 유지), `--session-affinity`. 공개 HTTPS URL을 QR에 넣는다.
- SQLite 파일은 컨테이너 안에 두면 재배포 시 사라지므로, 행사 중 재배포를 금지하고, 인스턴스 재시작 대비로 **스냅샷을 GCS 버킷에도 주기적으로(전이마다) 복사**한다. 기동 시 로컬 파일이 없으면 GCS에서 내려받는다.
- **예비 계획**: 참가자용 LAN 모드는 두지 않는다(핫스팟 접속 대수 제한). 대신 노트북 업링크 장애에 대비해 **백업 핫스팟 폰 1대**를 준비한다. 서버는 클라우드에 있으므로 노트북이 끊겨도 참가자 진행은 계속되고, 콘솔·스크린은 재접속 후 `room:state`로 복구한다. 클라우드 서버 자체의 장애는 인스턴스 재시작 + GCS 스냅샷 복구로 대응한다.

## 검토한 대안

| 대안 | 장점 | 단점 | 기각 이유 |
|---|---|---|---|
| 현장 노트북 LAN 서버 | 인터넷 불필요, 지연 최소 | 행사장 WiFi가 없고 휴대폰 핫스팟은 접속 기기 10대 내외로 제한되어 50명 수용 불가, 노트북 절전으로 서버 중단 위험, HTTPS 인증서 없어 Wake Lock·진동 등 일부 API 제한 | 인원 수용이 물리적으로 불가. 예비 계획에서도 제외 |
| Compute Engine VM 1대 | Cloud Run 제약 없음, 디스크 영속 | VM 관리(패치·재시작·인증서), 비용이 상시 발생 | 사용자에게 Cloud Run 절차가 이미 있고, 단일 인스턴스 제약은 플래그로 해결됨 |
| Fly.io / Railway 등 PaaS | 배포 쉬움, WebSocket 무제한 | 사내 계정·결제 신설, 익숙하지 않음 | 새 플랫폼 학습 비용 |
| Cloud Run 다중 인스턴스 + Redis | 확장성 | 단일 인스턴스 결정과 충돌 | [[ADR-0002-single-instance-state]] |

## 결과

- 좋아지는 것: 참가자는 자기 데이터로 접속하므로 현장 WiFi에 의존하지 않는다. HTTPS라 브라우저 API 제약이 없다. 배포 절차는 기존 스킬을 재사용한다.
- 감수하는 것: Cloud Run WebSocket은 요청당 최대 60분이라 그 시점에 재접속이 한 번 일어난다(Socket.IO가 자동 처리, 사용자 체감 없음). 인스턴스 1개 고정으로 행사 시간 동안 소액 비용이 상시 발생한다. 행사 중 `gcloud run deploy`를 하면 인스턴스가 바뀌어 인메모리 상태가 날아가므로 **행사 전날 배포 동결**을 운영 체크리스트에 넣는다. 행사장 인터넷은 노트북 핫스팟 하나에 달려 있으므로 백업 폰이 필수이고, 참가자 측 이동통신 장애(지하·차폐)는 앱으로 대응할 수 없으니 사전 답사에서 수신 상태를 확인한다.

> [!note] 확인됨 (2026-09-16)
> 행사장에는 유선 인터넷·WiFi가 없고 노트북은 휴대폰 핫스팟을 쓴다. 참가자는 자기 이동통신 데이터를 쓴다.
