# ADR-0003 참가자 식별은 전화번호를 자연키로 하고 계정은 만들지 않는다

## 맥락

사회자는 입장 시 전화번호와 이름(별명)을 받기로 했다. 전화번호가 필요한 이유는 (1) 한 사람이 폰 두 대나 탭 두 개로 두 자리를 차지하는 것을 막고, (2) 화면이 잠기거나 브라우저가 새로고침돼 세션이 날아갔을 때 **같은 사람을 같은 자리로 돌려놓고**, (3) 우승자에게 경품을 전달할 연락처를 남기는 것이다. 회원가입·비밀번호는 행사 입장 30초 안에 끝나야 하는 흐름에 맞지 않는다. 한편 전화번호는 개인정보보호법상 개인정보이므로 목적 고지·동의·파기가 필요하다.

## 결정

- 참가자의 자연키는 **정규화된 휴대폰 번호**(숫자만, 방 안에서 유일)다. 이름은 표시용이며 중복을 허용한다.
- 입장 시 서버가 **랜덤 세션 토큰**을 발급해 폰 localStorage에 저장하고, 소켓 연결 인증에 쓴다. 토큰이 없으면(다른 브라우저 등) 같은 전화번호를 다시 입력해 자리를 되찾는다.
- 계정·비밀번호·SMS 인증은 만들지 않는다.
- 전화번호는 **사회자 콘솔과 CSV에만** 보이고, 스크린·참가자 이벤트·URL·로그에는 절대 실리지 않는다. 입장 폼에 수집 목적과 보관 기간을 적고 동의 체크를 필수로 한다. 행사 후 콘솔의 삭제 버튼 또는 보관 기간(기본 7일) 경과 시 자동으로 번호를 지운다.

## 검토한 대안

| 대안 | 장점 | 단점 | 기각 이유 |
|---|---|---|---|
| 이름만 받고 세션은 토큰만으로 유지 | 개인정보 없음 | 토큰 유실 시 복귀 불가, 동명이인 구분 불가, 경품 연락처 없음 | 사회자 요구(전화번호 수집)에 반함 |
| SMS 인증번호로 본인 확인 | 대리 입장 방지 확실 | 발송 비용·지연, 통신 장애 시 입장 불가, 30초 입장 목표 붕괴 | 사내·지인 행사 수준에서 과잉 |
| 카카오/구글 로그인 | 구현된 인증 | 로그인 화면 이탈, 계정 없는 참가자 배제, 앱 심사·키 관리 | 입장 마찰이 가장 큼 |
| 전화번호를 해시로만 저장 | 유출 위험 감소 | 경품 연락이 불가능해져 수집 목적 자체가 사라짐 | 목적과 충돌. 대신 노출 경로 차단과 파기로 위험을 낮춤 |
| 전화번호를 URL 파라미터로 전달해 자동 입장 | 편리 | 브라우저 히스토리·프록시 로그에 번호가 남음 | 개인정보 노출 경로 |

## 결과

- 좋아지는 것: 입장이 폼 하나로 끝나고, 폰 사고(잠김·새로고침·배터리 교체) 후에도 자기 자리로 돌아온다. 사회자는 경품 연락처를 CSV로 바로 얻는다.
- 감수하는 것: 다른 사람의 번호를 아는 사람이 그 자리를 가로챌 수 있다(이름까지 일치해야 복귀 허용, 그래도 완전한 방어는 아님). 사내·지인 행사에서는 수용하고, 콘솔의 수동 개입([[game-flow]])으로 대응한다. 개인정보 고지 문구를 실제 사용 전에 확정해야 한다.
- 영향받는 문서: [[requirements]] FR-2·FR-3·FR-5·FR-41·FR-43, [[data-model]] `players`, [[realtime-protocol]] `POST /api/join`

> [!question] 확인 필요
> 입장 폼의 고지 문구(수집 항목·목적·보관 기간·담당자)는 회사 개인정보 담당자 확인이 필요하다. 보관 기간 기본값 7일이 경품 지급 일정과 맞는지도 확인해야 한다.
