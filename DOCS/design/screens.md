# 화면 설계

세 화면은 하나의 SPA 안의 라우트다. 참가자 폰은 세로, 스크린은 1920×1080 가로 전체화면, 사회자 콘솔은 노트북 가로 화면을 기준으로 한다.

동작 원칙:

- 입장 폼은 **첫 화면이 사용법**이다. 설명 문장은 두 줄 이하. 전화번호 입력은 숫자 키패드(`inputmode="numeric"`)와 자동 하이픈.
- O/X 버튼은 화면 절반씩 차지하는 큼직한 영역. 탭 시 진동(`navigator.vibrate`)과 색 반전으로 즉시 피드백하고, 서버 ack가 오면 체크 표시. ack가 1초 안에 안 오면 "전송 중…" 표시.
- 답변 화면에서 남의 선택은 보이지 않는다. 눈치 답변은 스크린을 보고 하는 것이 게임의 일부다.
- 화면은 `room:state`의 `canAnswer`로 갈린다. `WAITING`은 일반 라운드에서 문제는 보되 버튼 대신 "관전 중" 안내를, 패자부활전에서는 붉은 배너 "맞히면 복귀, 틀리면 탈락"과 함께 버튼을 본다. `ACTIVE`는 패자부활전 동안 "관전 중" 화면을 본다. 부활자(스트라이크 1)는 답변 화면 하단에 "남은 기회 1회"를 상시 표시.
- 탈락 화면은 소켓이 끊긴 뒤에도 그대로 남는다. 새로고침하면 서버가 `eliminated`로 거절하며 같은 화면을 다시 보여준다.
- 화면 잠김 방지를 위해 가능한 브라우저에서 Wake Lock API를 요청한다.
- 화면 맨 아래에 **채팅 서랍**이 있다. 접으면 마지막 메시지 한 줄만 보이고, 펼치면 최근 40건과 입력창이 나온다. 60자까지, 1.5초에 한 번. 한글 입력은 Enter를 두 번 누르면 전송된다(첫 Enter는 글자 확정). 사회자가 잠그면 입력창이 비활성된다.

### 답변 중 — 이동 숨김 모드 (기본 5번 문제부터)

```
 상단 자막 "🙈 이번 문제부터 선택은 마감 후 공개". 아바타는 전원 중앙에 머물며 배회하고,
 선택을 마친 사람 머리 위에 ✓ 배지만 뜬다(어느 쪽인지는 안 보임). 선택을 바꿔도 배지는 그대로.
 마감 순간 전원이 자기 구역으로 1.2초간 일제히 달려간 뒤 인원 숫자가 떠오른다.
 콘솔은 이 모드에서도 O/X 현황을 실시간으로 본다.
```

### 패자부활전 (무대 교대)

```
 진입:   상단 자막 "🔥 패자부활전 · 대기실 5명 도전". 무대 생존자 아바타가 하단 띠로 걸어 내려가고
         띠 이름이 "생존자석 38명"으로 바뀜(반투명). 대기실 아바타가 무대 중앙으로 올라옴. 2초 고정.
 답변:   일반 라운드와 같은 O/X 이동·타이머. 생존자석은 배회만 함.
 공개:   정답자는 "부활!" 꼬리표 + 색종이와 함께 무대에 남고, 오답자는 탈락 연출로 사라짐.
 다음:   일반 라운드로 넘어가면 생존자석 아바타가 무대로 올라와 부활자와 섞임. 띠는 다시 "대기실"(남은 인원)이 됨.
```

### 채팅 (말풍선 + 오른쪽 패널)

```
 ┌──────────────────────────────────────────────────────┬─────────────┐
 │ Q3 / 12   지구는 태양 주위를…            ⏱ 08        │ 💬 채팅      │
 ├──────────────┬──────────┬──────────────┐             │ ⚉민준 가자!! │
 │   O 구역      │  중앙     │   X 구역      │             │ ⚉수아 헐…    │
 │   ⚉ ⚉ ⚉      │  ┌──────┐│   ⚉ ⚉        │             │ ⚉도윤 O 확실 │
 │      ⚉       │  │3초남았│⚉│             │             │ ⚉서연 화이팅 │
 │              │  └──┬───┘ │              │             │             │
 │              │    ⚉테스터 │              │             │             │
 ├──────────────┴──────────┴──────────────┤             │             │
 │ 대기실 0명                                │             │             │
 └──────────────────────────────────────────┴─────────────┘
```

- 참가자가 폰에서 메시지를 보내면 **보낸 사람 아바타 위에 말풍선이 5초 동안** 떴다가 위로 사라진다. 같은 사람이 연달아 보내면 말풍선이 새 내용으로 바뀐다.
- 오른쪽 **채팅 패널**(340px)에 최근 14건이 아바타·이름과 함께 쌓인다. 채팅이 켜져 있으면 무대가 1460px로 줄고 구역·대기실 띠도 그만큼 좁아진다. 사회자가 채팅을 잠그면 패널이 사라지고 무대가 원래 너비로 돌아온다.
- 채팅은 서버 메모리에만 최근 200건 남고 저장하지 않는다. 게임 초기화 때 함께 비워진다.

### 사진 문제

문제에 사진이 있으면 중앙(미선택) 구역 윗부분에 액자 형태(480×380)로 크게 뜨고, 미선택 아바타는 그 아래 좁은 띠에서 배회한다. 참가자 폰에도 같은 사진이 지문 아래에 나온다. 사진은 콘솔 문제 편집기에서 올리며(브라우저가 1280px로 줄여 서버에 저장), 외부 URL을 직접 적어도 된다.

### 마감 → 정답 공개 → 종료

```
 마감:   (숨김 모드였다면 먼저 전원이 자기 구역으로 1.2초간 일제히 달려감)
         O 구역 위에 큰 숫자 "23명", X 구역 위에 "17명", 중앙에 "미응답 2명" 이 차례로 떠오름
 공개:   정답 구역이 밝게 빛나고 색종이. 오답 구역은 회색으로 어두워지며
         오답 아바타(0스트라이크)는 대기실 띠로 걸어 내려가고,
         오답 아바타(1스트라이크)는 "탈락" 꼬리표가 붙은 뒤 연기처럼 사라짐.
         상단에 "생존 38명 · 대기실 5명 · 탈락 4명"
 종료:   무대 중앙에 생존자 아바타가 모이고 이름이 크게 나열됨. 사회자가 생존자를 무대로 불러
         추가 문제나 가위바위보로 결승을 진행(앱 밖)한 뒤 콘솔에서 우승자를 지정하면
         그 아바타에 왕관 + 팡파르 + 색종이. 생존자가 처음부터 1명이면 곧바로 우승 연출.
```

### 아바타(미니미) 규칙

| 항목 | 설계 |
|---|---|
| 그림 | 몸 색(12) × 얼굴(8) × 머리/모자(10) 조합 = 960종. 시드는 입장 시 서버가 배정, 참가자가 폼에서 재추첨 가능. 파츠는 자체 제작 SVG로 저작권 문제 없음 |
| 크기 | 1080p 기준 64px(50명 내외), 100명 초과 시 48px로 자동 축소. 이름표는 아바타 아래 14~16px, 6자 넘으면 말줄임 |
| 유휴 움직임 | 클라이언트 전용. 현재 구역 안에서 임의 목표점을 골라 초당 20~40px로 걷고 1~4초 멈춤을 반복. 살짝 위아래로 통통 튀는 바운스. 서버는 위치를 모른다 |
| 구역 이동 | `answer:moved`를 받으면 목표 구역 안의 **빈 칸**(격자 슬롯)을 배정하고 걸어간다. 거리에 비례한 시간, 최대 1.2초. 도착 후 다시 유휴 상태. 숨김 모드에서는 `question:timeup`의 `choices`를 받아 전원이 동시에 출발 |
| 겹침 방지 | 구역마다 격자 슬롯을 두고 도착 순서대로 채움. 인원이 슬롯을 넘으면 격자 간격을 좁힘 |
| 연결 끊김 | 아바타가 반투명(50%)이 되고 이름표에 ⚡ 표시. 복귀하면 원래대로 |
| 대기실 띠 | 하단 띠. 일반 라운드에서는 관전 중이라 배회만 하고 O/X 이동 없음. 아바타는 축소 표시, 경고 표시로 노란 테두리. 패자부활전에서는 띠가 "생존자석"으로 바뀌어 무대와 역할을 교대 |
| 상태 복구 | `room:state`를 받으면 이동 연출 없이 최종 위치에 즉시 배치 |

### 효과음·연출

| 순간 | 연출 |
|---|---|
| 타이머 마지막 5초 | 숫자 붉게, 틱 소리, 화면 가장자리 펄스 |
| 마감 | 종소리, 아바타 이동 정지, 숫자 카운트업 |
| 정답 공개 | 정답 구역 플래시 + 색종이, 오답 구역 회색화 |
| 탈락 | 짧은 낮은 음 + 연기 파티클 |
| 우승 | 팡파르 + 왕관 |

브라우저 자동재생 정책 때문에 스크린을 띄운 뒤 사회자가 화면을 한 번 클릭해 "🔊 사운드 켜기"를 해야 한다. 로비 화면 구석에 버튼을 둔다.

## 3. 사회자 콘솔 (`/host`)

```
┌───────────────────────────────────────────────────────────────────────────┐
│ OX 퀴즈 콘솔      방 7K3P   상태: ANSWERING   ⏱ 00:07      [스크린 열기 ↗] │
├────────────────────────────────┬──────────────────────────────────────────┤
│ 진행                            │ 참가자 (42)   생존 38 · 대기실 5 · 탈락 4  │
│                                 │ 🔍 이름/번호 검색                          │
│ Q3 / 10                         │ ┌──────────────────────────────────────┐ │
│ "지구는 태양 주위를 1년에…"        │ │ 김철수  010-****-5678  ACTIVE   ● O  │ │
│ 정답: O  (스크린엔 안 보임)        │ │ 이영희  010-****-6789  WAITING  ● X  │ │
│                                 │ │ 박민수  010-****-7890  ELIM(Q2) ○    │ │

│ [+10초] [지금 마감]               │ 선택한 참가자: [복구] [퇴장]               │
│                                 │                                          │
```

동작 원칙:

- **"다음 단계" 버튼 하나**가 상태에 따라 라벨이 바뀐다: 입장 마감 → 문제 공개 → (3초 준비 카운트 뒤 타이머 자동 시작, 버튼은 "N초 뒤 자동 시작 · 지금 시작") → (자동 마감) → 정답 공개 → 다음 문제. 사회자는 문제 공개와 정답 공개만 눌러도 진행된다. 설정 탭에서 자동 시작을 끄면 예전처럼 "타이머 시작"을 직접 누른다.
- 설정의 예정 시점(기본 5번 문제) 정답 공개 뒤에는 **"다음 단계" 버튼 자체가 "패자부활전 시작 (대기실 N명)"으로 바뀐다**. 사회자는 평소처럼 큰 버튼만 누르면 된다. 그 외 시점에는 부활 버튼이 보조 버튼으로 남고, 이미 한 번 열었으면 "추가 부활전 (비상용)"으로 라벨이 바뀌며 2단계 확인을 받는다. 대기실 0명이면 비활성. 패자부활전 중에는 상단 상태 표시가 붉게 바뀌어 모드를 헷갈리지 않게 한다.
- 위험한 버튼(판정 취소, 게임 종료, 전화번호 삭제)은 2단계 확인.
- 전화번호는 이 화면에만 보이고, 스크린 공유 사고를 막기 위해 기본은 마스킹(`010-****-5678`), 클릭 시 전체 표시.
- 콘솔은 스크린과 다른 창·다른 기기에서 열어도 된다. 노트북 화면을 프로젝터에 복제하는 경우를 위해 "스크린 열기"가 새 창을 띄운다.
- 문제 불러오기 형식: CSV 열 `order,kind,text,answer,timeLimitSec,imageUrl,explanation`(한글 헤더 `문제,정답,종류,제한시간,이미지,해설`도 됨). `kind`는 `NORMAL`/`REVIVAL`(비우면 `NORMAL`), 정답은 `O`/`X`만 허용, 검증 실패 행을 표시. 저장소의 `questions/sample-questions.csv`가 예시.
- 문제 편집기의 **📷 사진 선택**으로 사진 문제를 만든다. 선택한 파일은 브라우저에서 긴 변 1280px로 줄여 서버에 올라가고, 편집기와 목록에 썸네일이 보인다. 외부 URL 입력도 가능하지만 행사장 인터넷 상태에 좌우되므로 직접 올리는 쪽을 권장.
- 게임 종료 화면에서는 생존자 목록 옆에 **[우승자 지정]** 버튼이 생긴다. 무대에서 추가 문제나 가위바위보로 결승을 끝낸 뒤 한 명을 고르면 스크린에 왕관이 뜬다. 잘못 골랐으면 다시 고를 수 있다.
- 콘솔은 이동 숨김 모드와 무관하게 항상 O/X 현황을 실시간으로 본다. 노트북 화면을 프로젝터에 복제하는 경우 이 숫자가 노출되므로, 반드시 스크린 창을 따로 띄워 프로젝터로 보낸다.
